# HDR Photo Viewer — исследовательский прототип 0.2

Нативный просмотрщик для Apple Silicon, macOS 15+. Исходники на Swift/AppKit, без сторонних библиотек. Дата проверки документации: 30 октября 2026.

**Статус: предварительная версия, скомпилирована на GitHub Actions (macOS 15 arm64, Xcode 16.4).** Проверки JPEG/EXIF orientation, повреждённого файла, сохранения float HDR и нейтрального HDR-блика при SDR tone mapping прошли. Визуальная проверка интерфейса и реальных HDR-фотографий ещё необходима. Готовые DMG после успешного завершения сборки публикуются в Releases.

## Сборка и использование

1. Установите Xcode 16+ либо Command Line Tools с macOS 15+ SDK. Если Xcode уже установлен, выберите его в Xcode → Settings → Locations → Command Line Tools.
2. Откройте `build.command` в этой папке. Он компилирует arm64-приложение, создаёт локальную ad-hoc подпись и открывает `build/HDR Photo Viewer.app`.
3. Откройте фото через «Фото…» / ⌘O или папку через «Папка…» / ⇧⌘O. Можно перетащить файл или папку в область просмотра. Выбор файла также открывает его папку во встроенном проводнике.
4. Для создания установочного образа откройте `package-dmg.command`: он собирает приложение и создаёт `build/HDR Photo Viewer.dmg` со ссылкой на «Программы».

Локальная подпись не является Developer ID или нотариализацией для распространения. Исходные фотографии не изменяются и не отправляются в сеть. В сборке нет зависимостей, требующих загрузки.

## Что реализовано

- Core Image читает HDR и SDR представления отдельно, учитывая EXIF orientation.
- `.expandToHDR: true` запрашивает восстановление HDR. Декодирование зависит от формата и поддержки установленной macOS.
- `CIToneMapHeadroom` адаптирует известный HDR headroom к текущему диапазону экрана.
- `MTKView`/`CAMetalLayer`: `rgba16Float`, EDR включён, extended linear Display P3. Профиль входного изображения не заменяется профилем P3: Core Image выполняет преобразование цветов.
- Изменение доступного диапазона проверяется дважды в секунду; непрерывный цикл рисования не используется.
- При диапазоне экрана 1×, выборе SDR или неизвестном HDR headroom используется отдельно декодированное SDR-представление. Для HDR без SDR базы запрошен системный HDR→SDR tone mapping.
- Показываются размеры, заявленный исходный профиль, HDR headroom и результат поиска старой Apple gain map. Отсутствие этой auxiliary map **не доказывает отсутствие Adaptive HDR**.
- Ошибки чтения и рендеринга выводятся в окне. RAW отвергается явно. Изображение вписывается в окно; масштаб 1:1 и панорамирование пока не реализованы.


## Проводник и листание (версия 0.2)

- Боковая панель показывает подпапки и фотографии с миниатюрами. Папки открываются двойным щелчком; снимки выбираются одним щелчком.
- Есть путь к папке (двойной щелчок по компоненту), история назад/вперёд, переход вверх и обновление. Быстрые переходы: домашняя папка, «Изображения», диски.
- Файлы сортируются по имени естественным порядком: IMG_2 перед IMG_10. Папки идут первыми; скрытые файлы и пакеты приложений пропускаются.
- ← / → и кнопки над фото переключают снимки в текущей папке. На первом и последнем снимке листание останавливается. Подпапки не включаются в последовательность фотографий.
- F, Control–Command–F или двойной щелчок по миниатюре включают полный экран. Esc выходит из него. Боковая панель и подписи скрываются, ← / → продолжают работать.
- ⌘B показывает/скрывает проводник. После выхода из полного экрана восстанавливается его прежнее состояние.
- Стрелки перехватываются только в окне просмотрщика, не в диалогах выбора файла и не при редактировании текста. Клавиши ↑/↓ остаются для выбора строк в проводнике.
- Миниатюры читаются в фоне, одновременно не более двух, и хранятся в ограниченном кеше. Они служат для выбора файла; оценивать HDR нужно в большой области просмотра.
- При переходе в другую папку список заменяется целиком; устаревшие результаты чтения игнорируются. При быстром листании очередные ещё не начавшиеся загрузки отменяются, а результаты старых не меняют выбранное фото.

Это встроенный браузер файлов с просмотром, а не каталог с базой данных, рейтингами и редактированием метаданных. Для появления новых файлов в открытой папке используется кнопка ↻.

Дополнительная проверка после сборки: папка с IMG_1/IMG_2/IMG_10, пустая папка, недоступная папка, повреждённое фото, длинные имена, переход назад/вперёд, выбор файла из другой папки, долгое удержание стрелки, начало/конец списка, полный экран и возврат, стрелки в диалоге открытия, обновление после удаления текущего файла.

## Почему эта архитектура

Apple документирует восстановление Apple gain maps через Core Image начиная с macOS 14. В macOS 15 тот же механизм расширен на Adaptive HDR; доступны `contentHeadroom` и `CIToneMapHeadroom`. ImageIO предоставляет альтернативный путь через `kCGImageSourceDecodeRequest: kCGImageSourceDecodeToHDR`. В этом прототипе ImageIO используется для типа файла и метаданных, а Core Image — для декодирования и рендеринга. [Apple: HDR pipeline](https://developer.apple.com/videos/play/wwdc2024/10177/), [expandToHDR](https://developer.apple.com/documentation/coreimage/ciimageoption/expandtohdr), [toneMapHeadroom](https://developer.apple.com/documentation/coreimage/cifilter-swift.class/tonemapheadroom()).

В macOS 26 появился `CIFilter.systemToneMap()` и дополнительные средства HDR-статистики и настройки динамического диапазона. Это перспективный второй backend для сравнения с системными приложениями, но он не подходит как обязательная зависимость для установленной здесь macOS 15.7.5. [systemToneMap](https://developer.apple.com/documentation/coreimage/cifilter-swift.class/systemtonemap()), [современные HDR API](https://developer.apple.com/documentation/coregraphics/adopting-advancements-in-hdr-image-rendering).

Metal сам по себе не распознаёт gain map и не восстанавливает творческую обработку. Он выводит подготовленные пиксели. Float-буфер и расширенное линейное пространство сохраняют значения выше SDR white; системное управление цветом связывает их с экраном. [Apple: EDR через Core Image и Metal](https://developer.apple.com/videos/play/wwdc2022/10114/).

## Форматы и границы совместимости

| Вход | Ожидаемый путь | Статус |
|---|---|---|
| HEIC с Apple gain map | Системное HDR-декодирование | Нужен тест оригинала |
| HEIC/JPEG Adaptive HDR | Системный декодер macOS 15+ | Нужен тест оригинала |
| JPEG Adobe/Ultra HDR gain map | Зависит от конкретной разметки и версии ОС | Не гарантируется |
| SDR JPEG/HEIC | SDR, без искусственного усиления | Нужен runtime-тест |
| PQ/HLG файл, распознаваемый Core Image | HDR + системная SDR-версия | Нужен runtime-тест |
| RAW / ProRAW DNG | Явный отказ | Вне MVP |

Расширение JPEG/HEIC само по себе не подтверждает HDR. Если декодер возвращает headroom 1, интерфейс пишет «Декодер сообщает SDR»; это не доказательство отсутствия неподдерживаемой карты усиления. При headroom 0 приложение консервативно показывает SDR вместо выдуманного HDR. Определение всех вариантов gain maps и собственный декодер Adobe/Ultra HDR в MVP не включены. [Adobe: Gain Maps](https://helpx.adobe.com/sg/camera-raw/desktop/hdr-and-advanced-output/gain-map.html).

## Похожесть на iPhone Photos и Adobe Camera Raw

Цель — корректное использование информации, уже записанной в фотографии. Побитовое или визуально точное совпадение не доказано. Photos может учитывать собственные правки и окружение отображения; Camera Raw имеет настройки HDR/SDR, обработки и экспорта. Для сравнения нужен один и тот же исходный файл и согласованные настройки. [Adobe: HDR Output](https://helpx.adobe.com/au/camera-raw/desktop/hdr-and-advanced-output/hdr-output.html).

HEIC/JPEG содержат уже проявленные изображения. RAW demosaicing восстанавливает цвет из мозаичных показаний сенсора; восстановление HDR по gain map решает другую задачу. ProRAW может содержать уже демозаицированные линейные данные — его нельзя автоматически приравнивать к обычному Bayer RAW. Отдельный RAW backend потребует политики white balance, профилей камеры, шумоподавления и тональных кривых; он не воспроизведёт обработку Adobe автоматически.

У встроенного дисплея MacBook Air M1 заявлены P3 и яркость 400 нит. Это ограничивает физическое совпадение с яркими HDR-дисплеями iPhone. Наличие M1 не гарантирует большой EDR headroom. Приложение опирается на измеренное значение NSScreen, а не название устройства. [Спецификация Apple](https://support.apple.com/en-ie/111883).

## Проверки перед признанием рабочей версией

Выполнено: проверены сигнатуры и доступность основных API по документации Apple; `plutil -lint` прошёл; синтаксис `build.command` проверен `bash -n`; отсутствие компилятора корректно обработано. Запрос NSScreen из среды выполнения вернул пустой список — фактический headroom экрана не измерен.

Дополнительно выполнено на GitHub Actions: компиляция Swift для arm64, JPEG/EXIF decode, отклонение повреждённого файла, float HDR без clipping и нейтральный блик после tone mapping к SDR. В тесте исходные значения [2.0, 1.5, 0.5] сохраняются; нейтральный [2, 2, 2] после отображения к headroom 1 становится приблизительно [1, 1, 1]. Насыщенные цветные каналы могут выходить за reference white и не используются для этой проверки яркости.

Не выполнено: визуальная проверка интерфейса, GPU-рендеринг на пользовательском экране, визуальное сравнение HDR, тесты реальных gain maps. Фотографии пользователя не предоставлены.

После установки инструментов:

1. Собрать и открыть приложение. Проверить изменение размера, полный экран, ошибки файла, повторное открытие, быстрый выбор нескольких файлов.
2. Проверить портрет и EXIF orientation 1–8 с асимметричной тестовой мишенью: верх/низ, повороты и зеркальные варианты.
3. Сравнить SDR sRGB и Display P3 мишени с Preview: правильность цветов, нейтральный серый, отсутствие лишнего усиления.
4. Открыть оригинал iPhone с Apple gain map, Adaptive HDR HEIC и JPEG, отдельный Adobe gain-map JPEG. Записать ОС, профиль, content headroom и display headroom для каждого. Нераспознанные варианты не считать поддержанными.
5. Проверить SDR на экране с headroom 1 и принудительный SDR. Для SDR-базового gain-map файла сравнить с базовым изображением без карты.
6. Изменить яркость, питание и экран, проверить обновление статуса и сохранение деталей бликов. На HDR-экране проверить значения выше SDR white.
7. Сопоставить с Photos и ACR на одном Mac, затем с iPhone. Использовать оригинал без пересохранения; отключить Night Shift/True Tone для контролируемого сравнения, согласовать правки и HDR-настройки. SDR-скриншот не является надёжным измерением HDR-яркости.

Следующий практический шаг: сборка с SDK и тест 2–3 оригинальных HEIC/JPEG пользователя. Без этого нельзя честно назвать прототип проверенным просмотрщиком.
